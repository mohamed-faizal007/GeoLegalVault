Now the negative cases. The same user tries again, but the browser reports a place about 100 kilometres outside the zone. The server answers GEOFENCE_DENIED, and nothing is stored. The server decides inside or outside, never the browser. Now the location is inside the zone, but very imprecise: plus or minus 500 metres. The server refuses that too, with LOCATION_LOW_CONFIDENCE. This is called fail-closed: if the system is not sure, it says no. This machine allows up to 300 metres of uncertainty. In the supplementary view, the zone denial is written to the audit log with the claimed position. An honest limit: browser location can be faked, for example with developer tools. So geofencing here is a policy control that adds a layer. It is not a guarantee. The tamper-evidence comes from the blockchain, not from the geofence.
