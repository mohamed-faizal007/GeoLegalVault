KEY TERMS

Geofence: a virtual boundary drawn on a map; uploads and

approvals are allowed only inside it.

SHA-256 hash: a 64-character fingerprint of a file; change

one byte and the whole fingerprint changes.

Anchor / anchoring: writing that fingerprint (never the

file) to the public Sepolia test network.

Sepolia: a free Ethereum test network. Test Ether has no

real value.

Maker-checker: the person who made a document may not be

the one who approves it.

Clearance: Public < Internal < Confidential < Restricted <

Top Secret; a document above yours is a 404.

404 vs 403: 404 = not found, 403 = forbidden. 404 is used

so a hidden document is not confirmed to exist.

Pre-signed link: a download link that works for 60

seconds; the file never passes through the API.

Supplementary view: a read-only look at the database or

storage, labelled as such, not part of the app.

Fail-closed: if the system is not sure about the location,

it says no.

Service wallet: the one backend wallet that signs every

anchor; users never sign.

Merkle tree: a batching scheme for hashes; not used here.

One hash per file.



THREE HONEST LIMITS - DO NOT SKIP

1. At 0:45: Anyone can recompute the fingerprint later and

check the file. This is tamper-evident: changes are

detected, not prevented.

2. At 5:36: An honest limit: browser location can be

faked, for example with developer tools. So geofencing

here is policy, not a guarantee of where someone is. The

tamper-evidence comes from the blockchain.

3. At 18:24: One honest gap: the audit log has no hash

chain yet, so database writers could alter it.

Say: prototype, Sepolia test network, tamper-evident,

policy-level geofencing. Never say: tamper-proof,

unhackable, guaranteed location.
